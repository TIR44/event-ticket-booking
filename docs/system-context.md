# Системный контекст

Диаграмма показывает границу проектируемой системы и внешние зависимости. Внутренняя декомпозиция будет определена после моделирования предметной области.

```mermaid
flowchart LR
    buyer["Покупатель"]
    organizer["Организатор"]
    system["Event Ticket Booking"]
    payment["Внешний платёжный провайдер"]
    notifications["Внешний сервис уведомлений"]

    buyer -->|"Ищет мероприятие, резервирует место, оформляет заказ"| system
    system -->|"Показывает доступность, состояние заказа и билет"| buyer

    organizer -->|"Управляет мероприятиями, сеансами и схемами залов"| system
    system -->|"Показывает состояние продаж"| organizer

    system -->|"Создаёт платёж и проверяет его состояние"| payment
    payment -->|"Сообщает результат операции"| system

    system -->|"Передаёт подтверждение и билет"| notifications
    notifications -->|"Сообщает результат доставки"| system
```

## Ответственность системы

- управлять мероприятиями, сеансами и доступностью мест;
- создавать и завершать временные резервы;
- вести жизненный цикл заказа;
- регистрировать платёжные попытки и согласовывать результат с провайдером;
- выпускать электронный билет;
- инициировать уведомление и хранить состояние доставки.

## Внешние ответственности

Платёжный провайдер принимает платёжные реквизиты и выполняет денежную операцию. Event Ticket Booking не хранит данные банковской карты.

Сервис уведомлений отвечает за физическую доставку сообщения. Его недоступность не влияет на сохранность заказа или билета.
