# ДЗ 2. Декомпозиция сквозного проекта на сервисы

Тема №6: «Чек-аут / бронирование», Event Ticket Booking. [Карточка OTUS](https://otus.ru/learning/538096/#/homework-chat/51645/). Результат — архитектурная документация, не реализация приложения.

## Краткое обоснование

Покупатель резервирует место, оплачивает заказ и получает билет. Отличие темы — уникальное ограниченное право, поэтому доступность, резерв, заказ и билет образуют core-контекст Booking. Они меняются в одной транзакции. В первой версии заказ содержит одно место; это явное учебное ограничение.

Выделены семь возможностей и четыре владельца: Catalog публикует сеансы; Booking защищает право; Payments ведёт денежную операцию; Notifications доставляет результат. Каталог поддерживает core, оплата и доставка используют стандартные внешние возможности. [Таблица классификации](../domain-model.md) показывает, почему семь действий не требуют семи микросервисов.

Каждый владелец имеет отдельную БД и роль. Одна PostgreSQL-инсталляция допустима; общей бизнес-БД и запросов к чужим таблицам нет. Пока границы развиваются, сервисы упакованы в один backend-артефакт. Это не четыре независимых деплоя. Так карта сервисов согласуется с исходным модульным монолитом.

Cohesion Booking объясняется одним инвариантом, Payments — семантикой денежных результатов, Notifications — доставкой. Риск coupling — банковские статусы внутри Booking. PaymentPort и PaymentGateway направляют зависимости к контрактам; только адаптер знает API банка. Другой риск — отмена заказа из-за письма: Notifications не имеет такой команды.

Цена раздельных данных — отсутствие общей транзакции между владельцами. Результат оплаты доставляется через durable outbox, получатель фиксирует inbox вместе со своим изменением. Потеря ACK приводит к повтору. Поздний успех не выдаёт билет: Booking сохраняет истечение и запрашивает компенсацию. Это защищает уже следующего покупателя места.

## Пояснение для разбора

Показать конкуренцию за одно место и атомарную границу Booking. Пройти путь успеха и поздней оплаты на Context Map. Объяснить цену: приватные данные требуют восстановления, общая поставка не даёт независимых релизов. [Сценарии проверки](../booking-lifecycle.md) описывают ожидаемые исходы, не выданы за пройденные тесты приложения.
